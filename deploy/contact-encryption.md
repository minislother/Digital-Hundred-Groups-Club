# 个人信息加密部署与验证

## 保护范围

user 表的真实姓名 user_name、邮箱 email、手机号 phone 使用 AES-256-GCM。学号仍为现有业务关联编号，院系、简介等未加密；不宣称所有个人数据都已加密。密码仍使用 BCrypt。

密文格式 enc:v2:<密钥版本>:<Base64随机nonce及密文和认证标签>。认证附加数据包含版本与 user 字段用途，跨字段替换或篡改会失败。相同内容每次写入使用不同 nonce。尚未绑定用户编号，因此不能防御同一字段在不同用户行之间的密文调换。

## 配置

- CONTACT_ACTIVE_KEY_ID：当前写入版本，默认 primary，仅允许字母数字和下划线。
- CONTACT_KEY_primary：primary 版本的 32 字节随机密钥，Base64 编码。其他版本按 CONTACT_KEY_<版本> 配置，区分大小写。
- CONTACT_LOOKUP_KEY：独立生成的 32 字节随机 HMAC 密钥，Base64 编码，不得复用加密密钥。
- CONTACT_STRICT_READ：默认 true，拒绝非空明文及旧 v1 密文。仅迁移过渡临时设 false；损坏密文从不降级为明文。
- CONTACT_ENCRYPTION_KEY：只在迁移原 enc:v1 数据时保留旧密钥。

密钥只存服务端密钥管理系统，所有实例一致。不得提交、打印或放入镜像。Compose 示例只透传当前 primary 版本；轮换部署须显式加入旧、新版本环境变量。丢失密钥无法恢复密文。

## 上线顺序

1. 停止业务写入，备份数据库，并在副本演练。旧明文备份与 Excel 导入源文件仍需权限限制、存储加密及到期清理。
2. 执行 deploy/contact-encryption-schema.sql 一次。已执行过部分旧扩列操作时，应核对实际结构后执行缺失部分，不能重复添加列。
3. 配置上述密钥，以及 CONTACT_MIGRATION_JDBC_URL、CONTACT_MIGRATION_DB_USER、CONTACT_MIGRATION_DB_PASSWORD。
4. 使用项目编译类和完整运行依赖 classpath，执行 Java 主类 com.chinahitech.shop.utils.ContactEncryptionMigration。每批最多 500 条，游标与更新同事务提交到 contact_migration_progress；失败后同版本重跑会续跑。只允许运行一个迁移进程。
5. 使用同一主类加 `--verify` 参数执行全量验证。核验所有非空姓名/邮箱/手机号均为当前 v2 版本，三个 lookup 摘要与解密后重新计算一致。进度表仅说明执行位置，不替代完整核验。
6. 以 CONTACT_STRICT_READ=true 启动业务，验证三端登录、注册、联系方式修改、姓名精确搜索、导入、管理员列表、报名人列表。旧验证码缓存不再读取，用户需重新获取验证码，旧键按原 TTL 失效。

## 检索和轮换

三个 *_lookup 字段以 HMAC-SHA256 保存独立检索摘要，普通索引不承担唯一性约束。没有新增手机号或邮箱唯一的业务规则。邮箱只将域名转为小写，姓名和号码只去除首尾空白；不合并国家码，不支持片段搜索。现有姓名精确查询已改为摘要查询；后续联系方式精确查询应使用摘要，不能比较随机密文。

轮换加密密钥：先让所有实例具备旧、新读取密钥，再切换写入版本，停止写入并运行同一迁移工具。迁移进度按目标版本区分。完整核验且确认旧备份恢复策略后才能移除旧密钥。更换 HMAC 密钥必须停写、重建全部摘要，并重置该次迁移进度，不能直接替换环境变量。

## 展示和非数据库边界

超级管理员用户列表、活动报名人列表默认掩码展示联系方式。GET /topManager/contactDetail?userNumber=... 显式校验 TOP_MANAGER 权限，仅返回完整邮箱和电话。掩码不能提交为更新值；本人资料读取保持原有权限与展示。摘要不通过 JSON 暴露。

验证码 Redis 键改为 HMAC 摘要，日志补充姓名过滤，导入失败日志不输出消息正文。现有导入消息传文件路径，Excel 文件本身没有因数据库加密而被加密。该实现不替代 HTTPS、备份加密、数据库权限、磁盘加密及文件生命周期管理。

## 验证范围

使用独立 H2 MySQL 兼容内存库检查真实 SQL 参数绑定、MyBatis-Plus 通用读写及姓名摘要查询；它不等同于真实 MySQL 联调或报名高峰压测。生产数据库没有被本次代码变更自动修改。
